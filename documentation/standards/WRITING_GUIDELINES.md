# Writing Guidelines

## Voice

Write directly and operationally. Prefer clear instructions over marketing language.

## Structure

Each procedure should include:

- Purpose
- Prerequisites
- Steps
- Expected result
- Warnings
- Related topics

## Warnings

Warnings must explain the consequence.

Example:

> Warning: Do not run destructive purge commands without a reviewed dry-run report. This can remove operational records.

## Tips

Tips should be optional and practical.

## Data Safety

- Do not include passwords, tokens, database URLs, private phone numbers, emergency contacts, or full participant application JSON.
- Mask emails when examples need identity references.
- Use placeholders such as `<DATABASE_URL>` and `<USER_EMAIL>`.
